Same HTML.
Different machinery.

httpx — one plain HTTP request
Scrapy — a crawl framework: queues, retries, concurrency
Scrapling — anti-bot fetching, its own parser
Stealthy — a real browser, for pages that block you

They differ in how they get the page, not in what comes back — our pages don't block us and don't need JavaScript, so this is an operations choice, not a content one. (Scrapling also mangles citation markers, 299 times — ruled out.)

Part 1 · conclusion

The scraper barely matters

  • Same words. 100% between the three HTTP clients, 98% for the browser.
  • Same coverage. 98 of 100 pages, all four.
  • → so the scraper is an operations choice: throughput, retries, bot walls.

The converter is where the content actually gets decided.

Why it comes out this way: three of the four are the same HTTP GET with the same user agent, so the server hands back the same bytes — the libraries differ in scheduling and retries, not in content. Only the browser can differ, and this corpus does not need one: rendering changes the text on 1 page in 97. On a JavaScript-heavy corpus this result would not hold.
